\chapter{Known Issues \& Technical Debt}
\label{ch:known-issues}

This chapter used to list 21 items — every \textbf{KNOWN ISSUE} flagged earlier in this manual, collected in one place so a maintainer could find "what's currently wrong with this codebase" without reading 21 chapters first. All 21 have since been fixed (correctness bugs, security gaps, and most of the design/consistency debt), each in the chapter that originally flagged it, per this chapter's own house rule below. A pre-existing lint-debt problem discovered along the way (Chapter~\ref{ch:workflow}) has since been fixed too — and so has the 37-warning \code{react-hooks/exhaustive-deps}/\code{@next/next/no-img-element} debt that this chapter went on to flag once the error-level debt was clear, and the stock-Tailwind-to-\code{brand-*} token migration (Chapter~\ref{ch:styling}) this chapter flagged next. The remaining \code{alert()} consistency item below has since been closed out too, by a full security \& code-quality audit (Chapter~\ref{ch:playbook}) that also fixed several RLS gaps (Chapter~\ref{ch:rls}) and a notification-spoofing hole (Chapter~\ref{ch:server-actions}) that this chapter had never flagged in the first place — this manual only documents debt once someone finds it, not debt that exists but hasn't been noticed yet. \textbf{No error monitoring in production} was next on this chapter's own list; it's fixed too, now that \pathname{src/instrumentation.ts}, \pathname{src/instrumentation-client.ts}, \pathname{error.tsx}, and the new \pathname{global-error.tsx} all report to Sentry (Chapter~\ref{ch:envvars} documents the four new, all-optional environment variables this added). A same-day follow-up, done by actually querying the live Sentry API rather than trusting the dashboard by eye (Chapter~\ref{ch:playbook}'s new triage entry), found and fixed a real bug in that monitoring setup: server/edge stack frames for this app's own code were being misclassified as framework noise (\code{in\_app: false}) instead of highlighted, because Turbopack's bare-relative-path stack frames collide with both the Sentry SDK's and Sentry's backend's "is this a Node internal" heuristics — fixed in \pathname{src/instrumentation.ts}'s \code{beforeSend} hook, verified by re-triggering a test error and confirming the flag flipped via the API, not by assuming the fix worked. What's left is a short, honest list of what's still actually open.

\section{Still open}

\begin{enumerate}
  \item \textbf{\pathname{about-modal.tsx} still has a placeholder bio for one founder.} Owais Saleem's bio is real; Malik Umair's is still "Biography coming soon." — waiting on him to provide the text, not a code task. Chapter~\ref{ch:components}.
  \item \textbf{Automated test coverage is still growing.} Vitest covers a handful of pure functions (Chapter~\ref{ch:workflow}), and \pathname{tests/rls/} (Chapter~\ref{sec:rls-suite}) now exercises real RLS policies and role-gating triggers against a live local Supabase stack — but there is still no component or end-to-end (Playwright) coverage. Growing that is ongoing, incremental work, not a single fixable bug.
  \item \textbf{No general HTTP-level rate limiting.} The only rate limits that exist are two database triggers scoped narrowly to \code{messages} and \code{book\_requests} (Chapter~\ref{ch:functions}). Login, signup, and plain \code{/browse} traffic are unprotected. Chapter~\ref{ch:welcome}, Phase 1.
  \item \textbf{\pathname{browse/page.tsx}'s \code{.limit(200)} and \code{get\_books\_nearby}'s \code{p\_limit} are stopgaps, not real pagination.} Once the catalog exceeds a couple hundred available books, results past that cutoff silently stop appearing — no error, no "next page." Not urgent pre-launch; revisit once the catalog actually approaches that size. Chapter~\ref{ch:welcome}, Phase 1.
  \item \textbf{Admin list pages other than Books, Requests, and the settings audit log have no real pagination.} Users, Reports, and Content fetch a flat-capped result set instead. Lower priority than the item above since admin traffic is inherently small, but will degrade as those tables grow over months of real usage. Chapter~\ref{ch:pages}.
\end{enumerate}

If you fix one of the items above, delete its entry from this chapter in the same pull request — an item that's been fixed but still listed here is its own small instance of documentation drift, which is exactly the failure mode this chapter exists to avoid repeating.
\end{olknote}
